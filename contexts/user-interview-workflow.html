User Interview Workflow

ใช้ซ้ำทุก project. SaaS, e-commerce, internal tool. เริ่มจาก user และงานจริงก่อน feature, UI, code.

1

เลือก project และคำถามเดียว

เช่น ร้านค้า: ยอดขายรายวันคือปัญหาแรกไหม? E-commerce: ลูกค้าทิ้ง checkout เพราะอะไร?

2

เลือก user ที่เพิ่งทำงานนี้จริง

เริ่ม 3–5 คน. ถ้าธีมยังใหม่ ให้สัมภาษณ์ต่อ.

3

ถามเรื่องครั้งล่าสุด

ให้ user เล่า trigger, ขั้นตอน, เครื่องมือ, ปัญหา, workaround, ผลลัพธ์.

4

แยก fact ออกจากความคิด

Quote และสิ่งที่เห็น = evidence. สิ่งที่ทีมสรุป = interpretation.

5

หา pattern

รวม pain, workflow, user type, desired outcome จากหลาย interview.

6

สร้าง MVP จาก evidence

Problem, outcome, requirements, DDD, technical plan, UI, test.

คำถามหลัก

  • ครั้งล่าสุดทำงานนี้เมื่อไร?
  • ทำทีละขั้นอย่างไร?
  • ตรงไหนช้า ผิด หรือสับสน?
  • ตอนนี้แก้อย่างไร?
  • ผลลัพธ์ไหนสำคัญสุด?

ห้ามเริ่มแบบนี้

  • “อยากได้ feature อะไร?”
  • “ถ้าสร้างแล้วจะใช้ไหม?”
  • เอา insight project หนึ่ง ไปฟันธงอีก project

Use case ปัจจุบัน: ระบบบันทึกยอดขายร้านเล็ก

เริ่มจากร้านผลไม้ของแม่. เรียนรู้การขายจริง การจดกระดาษ การรวมยอด และข้อผิดพลาด. แล้วคุยกับร้านอื่นในกลุ่มเดียวกัน ก่อนตัดสินใจ MVP.

ใช้กับ project อื่น

เก็บ research index กลาง. แยก project, user, interview date, evidence, theme, decision. ใช้ insight ซ้ำได้เมื่อ user, task, context, problem เหมือนกันเท่านั้น.
